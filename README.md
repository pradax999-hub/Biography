# NIGHTWNTR 2.0

Иммерсивное портфолио: живая структура из частиц на WebGL, редакторская
типографика и рабочая форма заказа с онлайн-оплатой.

Собрано заново по опубликованному сайту nightwntr 1.0: весь контент, цены,
пять языков и логика заказа перенесены оттуда (см. [`docs/AUDIT.md`](docs/AUDIT.md)).

- **Фронтенд:** React 19, TypeScript, Vite, Three.js (свой GPU-движок на GLSL),
  GSAP + ScrollTrigger, Lenis.
- **Бэкенд:** одна функция Netlify (`/api/*`), хранилище Netlify Blobs,
  Stripe Checkout, уведомления в Telegram.
- Шрифты и библиотеки лежат в сборке, сторонних CDN нет.

## Быстрый старт

Нужен Node.js 20 или новее.

```sh
npm install
npm run dev          # http://localhost:5173
```

Этого достаточно, чтобы всё работало локально, включая оформление заказа и
оплату: без настроек включается встроенная **песочница оплаты** (деньги не
движутся, на всех экранах пометка «тестовый режим»). Заказы пишутся в папку
`.data/`.

```sh
npm test             # 79 тестов сервера: цены, заказы, подписи, Stripe, панель
npm run test:e2e     # 99 проверок в браузере (нужен запущенный npm run dev)
npm run build        # проверка типов + сборка в dist/
npm run preview      # собранный сайт на http://localhost:4173
```

Чтобы прогнать браузерные проверки на собранном сайте с боевыми заголовками
безопасности: `npm run build && npm run preview`, затем
`BASE_URL=http://localhost:4173 npm run test:e2e`.

`test:e2e` использует Playwright. Если его нет: `npm i -D playwright &&
npx playwright install chromium`.

## Как устроена сцена

Частицы живут в float-текстурах и считаются на видеокарте.

- **Формации.** Шесть форм (VOID, MIND, STRATA, KNOT, FIELD, ECLIPSE)
  генерируются шейдером один раз: жилистая мембрана, аттрактор Томаса,
  контурный рельеф, трилистник, пыль, кольцо затмения. Моделей и картинок нет.
- **Симуляция.** Позиции и скорости обновляются за один проход (MRT):
  пружина к «дому», бездивергентный поток шума, указатель (отталкивание,
  закрутка, увлечение; при зажатой кнопке притяжение), ударная волна.
- **Шлейфы.** Вторая маленькая симуляция: строка текстуры хранит историю
  головы, из неё рисуется лента. Часть лент следует за курсором.
- **Морфинг.** Скролл выдаёт одно число (сцена + прогресс), движок смешивает
  формации волной по облаку.
- **Пост.** Bloom пирамидой размытий, фильмическая кривая, виньетка, зерно.
- **Качество.** Пять уровней (от 16 тыс. до 262 тыс. частиц), выбор по
  устройству и слежение за частотой кадров с понижением на лету. Для проверки:
  `?q=ultra|high|medium|low|minimal`.
- **Устойчивость.** Вкладка скрыта — отрисовка стоит. Потеря контекста —
  восстановление. Нет WebGL2 — CSS-фон, движок даже не загружается.
  `prefers-reduced-motion` — спокойная сцена, без плавного скролла и курсора.

## Заказ и оплата

Подробно: [`docs/PAYMENTS.md`](docs/PAYMENTS.md).

Форма та же, что в 1.0: услуга → детали → контакты → оплата. Новое:

- заказ сохраняется на сервере, цена считается там же;
- владельцу приходит уведомление в Telegram (если настроен бот);
- способ «Картой онлайн» через Stripe Checkout с проверкой на сервере;
- статус заказа виден на сайте и обновляется сам.

Если API недоступен (например, сайт выложен как чистая статика), форма
работает как в 1.0: номер заказа создаётся в браузере, заказ нужно отправить
сообщением. Оплата картой в этом случае не предлагается.

### API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/config` | что можно знать браузеру: включена ли оплата и в каком режиме |
| `GET /api/health` | проверка настройки |
| `POST /api/orders` | создать заказ |
| `GET /api/orders/:id` | статус (нужен токен заказа или id сессии оплаты) |
| `POST /api/orders/:id/checkout` | открыть страницу оплаты |
| `POST /api/orders/:id/cancel` | клиент вернулся, не заплатив |
| `POST /api/webhooks/stripe` | вебхук Stripe (с подписью) |
| `GET /api/admin` | панель владельца: заказы, подтверждение ручных оплат |
| `GET /api/admin/orders` | список заказов (`ADMIN_TOKEN`) |
| `POST /api/admin/orders/:id/status` | отметить ручную оплату (`ADMIN_TOKEN`) |

## Переменные окружения

Шаблон с пояснениями: [`.env.example`](.env.example). Для локальной работы
скопируй его в `.env`. Все переменные серверные; в браузер не попадает ни одна.

| Переменная | Зачем |
| --- | --- |
| `PAYMENT_PROVIDER` | `stripe`, `sandbox` или пусто (оплата картой выключена) |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | ключи Stripe |
| `SANDBOX_WEBHOOK_SECRET` | секрет песочницы |
| `SITE_URL` | адрес сайта для возврата после оплаты |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | бот для уведомлений |
| `TELEGRAM_NOTIFY_DETAIL` | `full` или `minimal` |
| `ADMIN_TOKEN` | доступ к панели владельца `/api/admin` и к `/api/admin/*` |

База данных не нужна: на Netlify заказы лежат в Netlify Blobs (включается
само), локально — в файлах `.data/orders/`.

## Панель владельца

`https://ТВОЙ-САЙТ/api/admin` — список заказов со статусами и контактами,
кнопка «Оплата получена» для переводов по QR и оплат в чате, индикаторы
настройки. Вход по `ADMIN_TOKEN`. Локально: `ADMIN_TOKEN=test npm run dev`
и `http://localhost:5173/api/admin`.

## Telegram

1. Напиши [@BotFather](https://t.me/BotFather): `/newbot`, получи токен.
2. Отправь своему боту любое сообщение со своего аккаунта.
3. Открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найди
   `"chat":{"id":…}` — это `TELEGRAM_CHAT_ID`.
4. Задай обе переменные и передеплой.

Приходит: новый заказ, оплата получена, платёж в обработке, оплата не прошла,
нужна ручная проверка. В сообщениях нет данных карт, ключей и токенов.
Кнопка «Отправить в Telegram» у клиента работает независимо от бота.

## Деплой на Netlify

Репозиторий готов: `netlify.toml` задаёт сборку, папку `dist` и функцию.

1. В Netlify: **Add new site → Import an existing project**, выбери этот
   репозиторий. Команда сборки и папка подставятся из `netlify.toml`.
   Чтобы заменить сайт 1.0, подключи репозиторий к существующему сайту:
   **Site configuration → Build & deploy → Link repository**.
2. Задай переменные окружения (минимум для уведомлений: два ключа Telegram;
   для оплаты — см. `docs/PAYMENTS.md`).
3. Запусти деплой и открой `/api/health`.

Без переменных сайт тоже работает: форма заказа с QR-переводом и чатом, без
оплаты картой и без автоматических уведомлений.

Другой хостинг: `server/router.ts` — это функция `Request → Response`, её
можно обернуть под любую платформу; для хранения укажи `ORDER_STORE=file` и
постоянный диск или напиши свой адаптер в `server/store/`.
